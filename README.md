# PactPay Relayer

NestJS HTTP relayer for proof-bound Pact Privacy withdrawals, refunds, and DeFi on
configured EVM and TRON chains. Proofs and witnesses are generated by the
client; the relayer accepts only unsigned allowlisted `GravArc` or
`PactPrivacyDefiRouter` calldata, simulates it, signs it with the configured relayer
key, and tracks confirmation durably.

## Setup

```bash
npm install
cp .env.example .env
```

`config.json` uses the same public configuration format as
`pact-privacy-server`. It is authoritative for chain IDs, families, RPCs,
GravArc addresses, native currencies, and token identities. The relayer selects
the first HTTP(S) URL in `wallet.rpcUrls`, falling back to the top-level
`rpcUrl`; WebSocket URLs are not used for signing and submission.

`relayer.config.json` selects the public configuration through
`publicConfigPath` and contains relayer policy: confirmation counts, resource
estimates and limits, signing-key environment-variable names, and optional
token pricing. The service always loads `./relayer.config.json`; public paths do
not belong in `.env`. Keep only private keys and optional provider credentials
in `.env`, and never put key material in either JSON file. Review both files
before starting. Commit the public JSON configuration, but never commit `.env`.

The native token is enabled automatically with a 1:1 conversion. To enable an
ERC-20 or TRC-20 listed in `config.json`, add a matching `tokenPricing` entry to
that chain's relayer policy with `address`, `decimals`, and its CoinGecko
`priceAssetId`; also set the chain's `nativePriceAssetId`. The relayer fetches
USD prices from CoinGecko's keyless public API, derives the token/native ratio,
caches it briefly, and rejects unavailable or stale prices. `priceSafetyMarginBps`
adds a conversion-risk margin to non-native network fees.

Configured gas, energy, and bandwidth estimates are multiplied by the safety
multiplier before quoting. Immediately before signing, the relayer compares the
locked network-fee component with the actual simulated limit and rejects an
underfunded quote instead of risking an unprofitable transaction.

Refund quotes use `refundGasByTier` on EVM or `refundEnergyByTier` and
`refundBandwidthByTier` on TRON when configured. If omitted, the relayer uses a
conservative 2× fallback from the corresponding withdrawal estimates. Measured
production values should replace the fallback.

DeFi quotes use `defiGasByTier` on EVM and `defiEnergyByTier` plus
`defiBandwidthByTier` on TRON. DeFi calldata is bound to the configured router,
protocol/helper allowlist, fee, token, amount, tier, nullifier, and nonce. TRON
private re-deposit is rejected.

Run the service:

```bash
npm run build
npm run start:prod
```

## API

- `GET /status` returns relayer addresses, supported chains/tokens, operation
  availability, network-fee estimates by tier, and the 0.1% service-fee rate.
- `POST /v1/withdraw/quote` accepts `chainId`, canonical token address, gross
  base-unit `amount`, and circuit `tier`.
- `POST /v1/withdraw` accepts `chainId`, `quoteId`, and unsigned withdrawal
  `calldata`, returning a durable operation ID.
- `POST /v1/refund/quote` accepts `chainId`, canonical token address, gross
  base-unit refund `amount`, and circuit `tier`.
- `POST /v1/refund` accepts `chainId`, `quoteId`, and unsigned refund `calldata`,
  returning a durable operation ID.
- `POST /v1/defi/quote` accepts `chainId`, input token, routed base-unit amount,
  and circuit `tier`.
- `POST /v1/defi` accepts `chainId`, `quoteId`, and proof-bound DeFi router
  `calldata`, returning a durable operation ID.
- `GET /v1/operations/:id` returns queued, submitted, confirmed, or failed
  status without returning calldata or signed transaction payloads.

All amounts and fees in the API are integer base units. Quotes are
operation-specific, short-lived, and one-time. The proof must bind its exact fee
and returned relayer address.

## Deployment safety

Run one application instance per SQLite database. Put it behind a trusted HTTPS
reverse proxy with global traffic limits; set `trustProxy` only when every
direct connection comes from that proxy. Back up the database and protect the
relayer keys independently. The worker persists signed payloads before
broadcast and never creates replacements for transactions with unknown status.
The application also enforces a process-wide request budget, per-IP throttles,
per-chain queue limits, and one active worker per chain.
